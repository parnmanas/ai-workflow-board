# 반응형 UI 점검 — 2026-10-06

모바일 세션에서 프롬프트가 버튼 사이에 끼어 좁고 길게 늘어나는 화면을 기준으로,
현재 React UI를 실제 Chromium에서 점검하고 수정했다. 기존 문서 최신화 작업과 별도로
클라이언트 레이아웃, 상호작용, 브라우저 회귀 검사를 갱신했다.

## 확인한 문제와 변경

| 화면 | 확인한 문제 | 현재 동작 |
| --- | --- | --- |
| 세션 입력 | 명령·첨부·마이크·전송 버튼을 한 줄에 두고 오른쪽 64px도 예약해 입력 폭이 320px 화면에서 26px, 390px에서 92px까지 줄었다. | 입력 영역 폭이 640px 이하이면 프롬프트가 전체 행을 쓰고 버튼은 다음 행에 배치된다. 실행 중 Cancel/Queue도 같은 배치다. |
| 세션 헤더 | 긴 경로와 여러 설정·보조 동작이 대화 영역의 높이를 크게 차지했다. | 좁거나 낮은 화면은 Settings로 설정·경로·인증 정보를 펼친다. 상태와 Connect/Stop은 유지된다. 펼친 설정은 높이를 제한하고 내부 스크롤을 제공한다. |
| 알림 벨 | 하단 고정 음소거 버튼이 Send/Queue 클릭을 가렸다. | 음소거 버튼은 앱 상단에 배치한다. 브라우저 검사는 실제 전송 버튼 클릭을 확인한다. |
| 채팅·미션 대화 | 작은 대화 패널에서도 첨부와 긴 전송 버튼이 입력 폭을 차지했다. | 대화 입력도 컨테이너 폭을 기준으로 전체 행을 사용한다. 긴 placeholder를 짧게 정리했다. |
| 화면 높이·키보드 | `100vh`만으로는 모바일 브라우저의 보이는 영역과 키보드 높이 변화에 대응하기 어려웠다. | `100dvh`와 visual viewport 높이를 사용한다. 확대 중에는 높이 보정을 적용하지 않는다. 모달·Artifact 오버레이도 보이는 높이를 따른다. |
| 공통 헤더·모달 | 제목·설명·버튼이 서로 밀렸고, 입력 포커스 시 모바일 브라우저 확대가 발생할 수 있었다. | 작은 화면에서 제목과 동작을 행으로 나눈다. 모달 높이를 제한하고 footer를 줄바꿈한다. 작은 화면의 입력 글자는 16px이며 사용자 확대는 제한하지 않는다. |
| 티켓 상세 | 작은 화면에서 목록과 편집기를 좌우로 분할했다. `?ticket=`를 전역 미리보기가 먼저 소비해 편집기로 이동하지 못했다. | 좁은 화면의 편집기는 본문 전체를 사용한다. `/tickets`에서는 해당 페이지가 딥링크를 처리한다. 다른 화면의 미리보기에서 편집기로 이동할 수 있다. |
| 미션·팀 | 카드 제목과 동작이 좁은 화면에서 압축됐다. 미션 상세는 고정 폭 단계 목록과 대화를 나란히 놓았다. | 카드의 동작·메타데이터를 줄바꿈하고, 좁은 미션 상세는 Steps로 목록을 펼쳐 선택한다. 선택 후 단계 세션을 표시하고 미션 대화로 돌아갈 수 있다. |
| Runtime Hosts·Artifact | 태블릿에서 사이드바와 상세 패널까지 동시에 보여 본문이 좁아졌다. | 좁은 Hosts는 목록과 상세를 전환한다. Artifact는 좁은 화면에서 오버레이를 사용한다. |

## 검증 범위

[브라우저 테스트](../../apps/client/test/responsive-layout.e2e.mjs)는 실제 앱·라우터·React
컴포넌트를 실행하되, 서버와 Runtime Host의 응답은 테스트 데이터로 대체한다.

| 검사 | 화면 크기 또는 범위 |
| --- | --- |
| 세션 전송·명령·대기열·가로 넘침 | 320×568, 360×740, 390×844, 430×932, 768×1024, 1024×768, 1100×800, 1101×800, 1440×900, 1920×1080, 667×375 |
| 작업·설정 페이지와 새 세션 모달 | 320, 768, 1440px 폭, 높이 800px |
| 작성 중 화면 회전·크기 변경 | 390×844 → 667×375 → 1440×900 → 390×844 |
| 키보드와 확대 | visual viewport 높이 844→390→844 이벤트와 scale=2를 시뮬레이션; 입력과 새 세션 모달의 위치 검사 |
| 티켓·Host 이동 | 미리보기 → 편집기 → 닫기; Host 상세 → 목록 |
| 미션 단계 이동 | 320, 768px에서 Steps 펼치기 → 단계 세션 → 미션 대화 |

목록/상세를 포함한 점검 URL은 `/sessions`, `/sessions/:host`, `/tickets`, 티켓 상세,
`/projects`, 프로젝트 상세, `/missions`, 미션 상세, `/teams`, `/chat`, 채팅방,
`/hosts`, `/terminals`, `/settings`, ownership, members, credentials, channels,
API keys, Claude profiles의 20개 경로다. 긴 세션 제목·경로, 여러 런타임 설정,
첨부/명령/마이크 버튼, 티켓과 프로젝트 데이터를 사용한다. 모든 관리 목록을
실제 운영 데이터로 채운 검사는 아니다.

문서 전체의 가로 넘침, 세션/티켓 작업 영역의 넘침, 입력 폭·높이·위치, 실제 버튼 클릭을
검사한다. Kanban, 표, 코드, 탭 등의 의도적인 내부 스크롤은 허용한다.

## 실행과 결과

```bash
# 저장소 루트
npx playwright install chromium
npm run test:e2e:responsive -w client
npm test -w client
npm run build
```

- 반응형 브라우저 검사와 추가 미션 단계 이동 검사를 통과했다.
- 클라이언트 전체 검사: pretest 70개, 본 검사 819개 통과.
- 마지막 입력 배치 수정 후 세션·미션 대화 관련 검사 32개도 통과.
- 루트 Turbo 빌드: client, server, agent-manager 모두 통과.
- CI 브라우저 잡에 반응형 검사를 추가했다. 실패하면 화면 캡처를 artifact로 업로드한다.
- 로컬 화면 캡처는 git에서 제외되는 `apps/client/test-results/`에 생성된다.

실기기의 iOS/Android 키보드·주소창·notch, Safari/Firefox, 실제 음성 인식,
운영 네트워크와 Runtime Host 실행, 모든 데이터 조합·해상도를 전수 검사한 결과는 아니다.
visual viewport 검사는 키보드가 만드는 높이 변화의 시뮬레이션이다. 배포 후 실기기 확인을
통해 플랫폼별 차이를 추가로 확인할 수 있다.
