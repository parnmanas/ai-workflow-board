# Interface languages

AWB opens in **English** by default, regardless of the browser or operating
system language. Users can select English, 한국어, 日本語, or 中文（简体） from
the login screen, the bottom of the sidebar, or Settings → Device.

The preference is stored in this browser as `localStorage['awb.locale']` and
restored before the application first renders. It follows neither the account
nor the Runtime Host. Tabs on the same origin synchronize the preference.
When browser storage is unavailable, selection still works for the current
page. Switching languages updates the interface without reloading or resetting
form drafts and active sessions. Dates and numbers use the selected locale;
stored timestamps, currencies, and amounts retain their original meaning.

Interface copy is translated. Usernames, project and ticket content, comments,
agent replies, native transcripts, command output, and provider-supplied details
retain their original text. Language selection does not change existing agent
prompts or speech-engine configuration. Product names, file paths, identifiers,
API enum values, authentication headers, and Account ownership fields remain
stable across languages.

The server's immutable business service catalog, connector setup instructions,
and self-service guidance are interface copy too. `i18n/catalog.ts` translates
only their explicitly listed display fields. IDs, configuration options,
URLs, prices, and user records keep their original meaning. Already loaded
catalogs respond to language changes without another API call.

## Adding or changing copy

The implementation lives in `apps/client/src/i18n/`. `core.ts` owns locale
selection and message lookup; `react.tsx` subscribes components through
`useSyncExternalStore`. The English catalog is included at startup. The other
three catalogs load on demand and are cached for later switches. A failed
download keeps the existing language and displays a retry message; a failed
startup restore falls back to English.

Add a literal message key to all four JSON catalogs in `locales/`. Use English
keys for new copy. Existing keys include the original Korean or English text
so that their use remains traceable to the original interface. Missing
translations fall back to the English catalog, then to the key. Do not pass
user-provided strings to the translation function.

```tsx
import { t } from '../i18n/core';
import { useLocale } from '../i18n/react';

function SaveButton({ count }: { count: number }) {
  useLocale();
  return <button>{t('Save {count} items', { count })}</button>;
}
```

Translate complete sentences with placeholders rather than concatenating
fragments. Preserve every `{name}` placeholder in every language. Parameters
are interpolated once as text; React continues to escape the result. For
language-dependent `useMemo` results, include the value returned by `useLocale`
in the dependency list. Keep network callbacks and loading effects independent
of locale so selecting a language does not discard work or reload data.

Static metadata must resolve labels at render time, for example through a
getter or a label function. Keep object keys, React keys, persisted navigation
IDs, status values, CSV input aliases, and request payloads independent of
translated display labels. Use `getLocaleTag()` for `Intl` and locale-aware date
and number formatting.

## Verification

Run `npm test -w client`, `npm run test:e2e:i18n -w client`, and the business
header browser suite:

```sh
PLAYWRIGHT_TEST_MATCH=business-header.e2e.mjs npm run test:e2e -w client
```

The localization tests cover the English default, persistence, storage denial,
live switching, preserved drafts and user content, catalog coverage and
placeholder parity, plus unchanged authentication headers and API data in all
four languages. Browser checks exercise login and authenticated navigation.
Business header checks cover the four languages on narrow mobile screens,
tablets with the sidebar open, and landscape screens, including actual menu
and button access. Existing content fixtures may explicitly select Korean;
tests of the default interface use English.
